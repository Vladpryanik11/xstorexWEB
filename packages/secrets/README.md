# @xstore/secrets

Серверная библиотека из M3, задача 1. Node.js 24+, ESM. Пакет не подключает API, воркер или базу данных.

`loadKeyring(process.env)` вызывается при старте доверенного процесса. Нужны `MASTER_KEY_CURRENT` (положительная целая версия) и `MASTER_KEY_V<n>` (ровно 32 байта, канонический base64). Все переданные старые ключи тоже проверяются; отсутствующий текущий ключ останавливает запуск. Реальные ключи генерируются и передаются вне git.

```ts
import { loadKeyring } from '@xstore/secrets';
import { encryptSecret } from '@xstore/secrets/encrypt';
// Только packages/apple, apps/worker и apps/api/src/apple:
import { decryptSecret, reencrypt } from '@xstore/secrets/decrypt';
```

Формат: `v<version>.<iv base64url>.<tag base64url>.<ciphertext base64url>`. AES-256-GCM; новый случайный IV 12 байт на каждую запись, тег 16 байт. Расшифровка возвращает Buffer; владелец очищает его после использования. `reencrypt` очищает свой временный открытый буфер. Ошибки формата, отсутствующего ключа и нарушения целостности различаются по классу, без исходных значений и причин от криптографической библиотеки.

Корневой экспорт не предоставляет расшифровку; browser-экспорты отключены. Это не заменяет правило контроля импортов.

## Проверка

После установки зависимостей из корня: `pnpm --filter @xstore/secrets test`, `pnpm --filter @xstore/secrets typecheck`, `pnpm --filter @xstore/secrets build`.

## Подключение после M1/M2

1. Пересоздать общий `pnpm-lock.yaml` вместе с `packages/apple` на актуальной ветке. Здесь файл намеренно не меняется, чтобы не пересекаться с M1. До этого `pnpm install --frozen-lockfile` в CI потребует обновления lockfile.
2. Внести правило Biome для `@xstore/secrets/decrypt`: разрешить импорт только внутри `packages/apple`, `apps/worker/**`, `apps/api/src/apple/**`. Проверить запрет реальным запуском линтера с импортом из каталога; проверить динамические импорты и re-export.
3. Добавить переменные окружения без реальных ключей в пример настроек; проверку `loadKeyring` — при старте соответствующих процессов.
4. Добавить redaction в pino API/воркера и интеграционный тест утечек. Пакет сам ничего не пишет в журнал; границы приложения проверяются отдельно.
5. После появления моделей M3 создать CLI ротации полей `*Enc` порциями по 100. Сначала развернуть ключи старой и новой версии, затем сменить текущую, перешифровать записи и только после проверки убрать старый ключ.

Эта поставка закрывает библиотечную часть задачи 1. CLI, ограничения импортов в монорепозитории и проверка журналов приложения входят в последующую интеграцию.
