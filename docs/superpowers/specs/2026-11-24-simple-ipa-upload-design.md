# Простая загрузка IPA и каталог «Удалённые / Премиум» — дизайн

Дата: 2026-11-24. Решение владельца в треде «Упростить загрузку приложений в админке» (18:04–18:13, «да» на макет https://claude.ai/artifact/KzpCvKwNbuRZ9iKLe71Cb8). Меняет спецификацию v2 §2, §3.1 п. 3, §3.4, §10 и правило CLAUDE.md об «основании для распространения».

## 1. Что хочет владелец

- «Очень сложная выгрузка в админке, нет хранилища, чтобы просто закинуть файлы».
- «Не надо добавлять сложностей, договор не договор — админам грузить без всяких сложностей».
- «Карточек приложений не будет, будет сам IPA-файл без скриншотов и прочего».
- «Максимум только каталог по категориям Удалённые, Премиум и придумать подкатегории».
- «Менять название и фото иконки, если надо».

## 2. Админка: один экран «Приложения» (`/admin/apps`)

Сверху вниз:

1. **Зона загрузки.** Голубая обтекаемая область «Перетащите IPA сюда», файлы можно бросить в любое место страницы и выбрать кнопкой. Много файлов сразу, до 10 ГБ каждый, докачка как сейчас (`upload-ipa.ts`).
2. **Загрузки в работе.** Список незавершённых и отклонённых загрузок хранится на сервере (`GET /admin/uploads`), поэтому не пропадает при закрытии вкладки. Строка: имя файла, «Загружается N%» (только в этой вкладке) / «Проверяем…» / «Не подошло: <причина и что делать>» и кнопка «Убрать». Удачные загрузки из этого списка уходят: файл стал строкой приложения.
3. **Фильтры-пилюли:** «Все», «Удалённые», «Премиум», «Без раздела», «Скрытые» (без чисел). Поиск по названию остаётся.
4. **Список приложений.** Строка: иконка, название, версия и размер последней версии, выбор раздела («Удалённые» / «Премиум»), выбор подкатегории, статус-капсула («В каталоге», «Ждёт раздела», «Ждёт подкатегории», «Скрыто», «Нельзя опубликовать: защищено App Store»), действия «Скрыть» / «Показать» и «Удалить».
   - **Название** правится прямо в строке: нажать → поле → Enter или уход с поля сохраняет, Esc отменяет.
   - **Иконка:** нажать на неё и выбрать PNG/JPEG до 5 МБ или бросить картинку на неё. Используется существующая загрузка медиа (`/admin/apps/:id/media/icon`).
   - **Удалить** спрашивает подтверждение прямо в строке («Удалить Spotify? Да / Нет»), без `confirm()`.
   - Нажатие на строку никуда не ведёт: страницы карточки нет.

Админка не показывает: описание, подзаголовок, разработчика, скриншоты, баннер, рейтинг, языки, «основание для распространения», «код дополнения», «что нового», отдельную публикацию версий. Страницы `/admin/apps/[id]` и `/admin/apps/upload` убираются (`/admin/apps/upload` перенаправляет на `/admin/apps`).

## 3. Публикация без кнопки

- Приложение попадает в каталог само, как только у него есть раздел, подкатегория, иконка и хотя бы одна версия без защиты App Store (FairPlay). Отдельной кнопки «Опубликовать» нет.
- При этом последняя незащищённая версия публикуется автоматически.
- Новая версия того же приложения (тот же bundleId) публикуется сама и заменяет старую в каталоге, если приложение уже в каталоге. Название и иконка, изменённые админом, сохраняются (иконка из IPA ставится, только если у приложения её нет — как сейчас).
- «Скрыть» убирает с сайта без потери файла (причина не спрашивается, пишется «Скрыто администратором»). «Показать» возвращает, если условия выполнены.
- Если админ убрал раздел или подкатегорию у опубликованного приложения — оно уходит в черновик («Ждёт раздела»).

Правила публикации в коде (`publish-rules.ts`): `NO_SECTION`, `NO_CATEGORY`, `NO_ICON`, `NO_VERSION` (нет незащищённой версии). `NO_RIGHTS_BASIS` убирается.

## 4. Разделы и подкатегории

- Новое поле `App.section` (`removed` | `premium`, пусто = «Без раздела»). `removedFromAppStore` держится равным `section = removed` для старого кода карточек.
- Миграция: `section = removed` для приложений с `removedFromAppStore`, `section = premium` для приложений из подборки `premium` (если не removed).
- Подкатегории — существующая модель `Category`, общая для обоих разделов. Миграция добавляет (если slug свободен): Музыка `music`, Кино и видео `video`, Фото и видео `photo`, Игры `games`, Соцсети `social`, Банки и финансы `finance`, Учёба и книги `education`, Полезное `tools`. Уже существующие категории не трогаем; список правится в «Категориях» админки как сейчас.

## 5. Сайт

- Разделы каталога в меню и на страницах: только «Удалённые из App Store» (`/removed`) и «Premium доступы» (`/premium`). «Популярные» и «Весь каталог» из меню убираются; адреса `/popular` и `/catalog` перенаправляют на `/removed`.
- На странице раздела — чипы подкатегорий этого раздела (только непустые), фильтр `?c=<slug>`, активный чип подсвечен, «Все» сбрасывает.
- `GET /catalog/sections/:slug?category=<slug>` фильтрует по подкатегории; `GET /catalog/sections/:slug/categories` отдаёт непустые подкатегории раздела.
- «Premium доступы» строится по `section = premium`, а не по подборке `premium`.
- Окно приложения и страница `/app/[slug]` уже переживают пустое описание — проверить тестом.

## 6. Правило о правах

Правило CLAUDE.md меняется: «Только IPA с правами на распространение; ответственность за права — на владельце. Взломанные приложения и „Premium“-моды не добавляем». Поле «основание для распространения» остаётся в базе, но не обязательно и не показывается в админке.

## 7. API (изменения)

- `GET /admin/uploads` — загрузки сотрудников со статусом `uploading` | `uploaded` | `inspecting` | `rejected` за 7 дней, новые сверху, до 100.
- `DELETE /admin/uploads/:id` — убрать незавершённую или отклонённую загрузку (прервать multipart, удалить объект, удалить запись). Готовую (`ready`) удалить нельзя (409).
- `GET /admin/apps` — добавляются `section`, `categoryId`, `sizeBytes` последней версии, `publishBlockers`, фильтр `section=removed|premium|none` (вместе с имеющимся `status`).
- `PATCH /admin/apps/:id` — принимает `section`; после любого изменения раздела, подкатегории, иконки сервер сам публикует или снимает с публикации (§3).
- `POST /admin/apps/:id/hide` — `reason` необязателен.
- `DELETE /admin/apps/:id` — удаляет приложение, версии и их файлы (IPA, иконки, подписанные копии) из хранилища. Пишется в журнал.

## 8. Тесты

- Модульные: правила публикации; авто-публикация; список загрузок; фильтры.
- Интеграционные: PATCH раздела публикует; новая версия публикуется сама; удаление приложения; `GET/DELETE /admin/uploads`; раздел с фильтром подкатегории.
- Компонентные: строка приложения (переименование, подтверждение удаления).
- E2E: админ загружает IPA, выбирает раздел и подкатегорию, приложение видно в `/removed`.
