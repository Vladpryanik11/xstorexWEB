## Сквозные договорённости

- **Новые пакеты:** `@xstore/ios` (разбор IPA, plist, Mach-O, CgBI, mobileprovision; M1, M3), `@xstore/secrets` (AES-256-GCM с версией ключа; M3), `@xstore/apple` (ASC-клиент, выбор аккаунта, OCSP; M3). Все только для Node, сайт их не импортирует.
- **Очереди:** `ipa` (M1), `notifications` (M2), `apple` (M3), `signing`, `maintenance` (M4), `billing` (M5). Задача пишется как `очередь:задача`, в данных задач только id, без секретов.
- **Ошибки:** все коды и русские тексты в `packages/shared/src/errors.ts` (`errorMessages`), API отдаёт `{ code, message, details? }`.
- **Настройки:** читаются через `readSetting` (M1), в M7 собираются в единый реестр со страницей в админке.
- **Права на установку:** одна чистая функция `canInstall` в `@xstore/shared`; M4 вводит её, M5 добавляет платные права, сигнатура не меняется.
- **Кнопка на странице приложения:** `installButtonState` и общий `resolveInstallAccess`: гостю «Установить» открывает предложение подписки со входом вторым действием; оплаченная подписка без UDID → подключение; готовый подписчик → установка. Доступ начинается после оплаты, а не после устройства.

## Решения владельца

Все решения приняты 2026-11-05: 1–4 владелец утвердил вместе со спецификацией, выбор 5–11 поручил исполнителю, и они приняты в том виде, как описаны ниже и в разделах «Owner decisions» планов. Способ выполнения: `superpowers:subagent-driven-development` (отдельный исполнитель на задачу и отдельный ревьюер перед следующей).

**Меняют спецификацию — утверждены владельцем 2026-11-05, внесены в spec (§5, §11, §14):**
1. Вход админов (пароль + TOTP) переезжает из M2 в M1: без него нельзя открыть админку каталога и загрузку IPA.
2. Новая сущность `IpaUpload` для отслеживания загрузок частями (M1, M6).
3. Новые поля `App`: `rating`, `ratingCount`, `languages`, `itunesId`, `bannerKey`, `hiddenReason` (нужны для «Самого рейтингового», полосы фактов, баннеров и скрытия по жалобе).
4. Новая таблица `Alert` для алертов админу и поля `Device.ascDeviceId`, `Device.includedInRevision`, раздельные слоты iPhone/iPad у аккаунта Apple (M3).

**Продуктовые и технические — приняты 2026-11-05:**
5. `.mobileconfig` подписывается сертификатом Let's Encrypt, который уже получает Caddy (M2).
6. UDID, привязанный к другому аккаунту, к чужому аккаунту не привязывается, одна почта на аккаунт (M2).
7. Wildcard App ID `*`, аккаунты заполняются по очереди, сертификаты ротируются за 30 дней без отзыва старых, дату членства вводит админ (M3).
8. Повторная загрузка манифеста iOS разрешена 120 секунд с того же клиента; zsign получает ключ PEM-файлами, без пароля в командной строке (M4).
9. Цены в целых рублях; возвраты делаются в кабинете Platega, админка только закрывает заказ и права; гарантия считается от начала последнего оплаченного периода (M5).
10. Корпоративные (enterprise) профили в Signer не принимаются; пользовательские сборки и иконки приватны (M6).
11. Пароль SMTP вводится в админке и хранится зашифрованным; CSP на первом релизе разрешает inline-скрипты; релиз — git-тег `v*` с подтверждением в GitHub (M7).


## Уточнение покупки от 2026-11-06 — утверждено владельцем

[Дополнение к спецификации](../specs/2026-11-06-purchase-and-activation-design.md) и обновлённые M2–M5 заменяют прежний порядок вход → UDID → оплата. Код пока остаётся на выполненной части M1.

- **Сценарий 1:** каталог → предложение подписки → тариф/email → оплата → подписка сразу активна → подключение iPhone → установка. M5 задача 7.
- **Сценарий 2:** существующий аккаунт → покупка/продление → немедленные права; уже подключённый iPhone не требует нового профиля. M5 задача 8.
- **Сценарий 3:** действующая подписка → установка, либо подключение/ожидание Apple без повторной оплаты. M5 задача 9.
- Последнее уточнение владельца: срок идёт с подтверждённой оплаты независимо от UDID/Apple. Обсуждавшееся начало после готовности отменено.
- `Subscription` принадлежит аккаунту и допускает отсутствие устройства. Позже назначается одному iPhone; даты не меняются. Продления складываются в её цепочке.
- Email checkout — контакт; обычный вход и восстановление требуют кода. UDID не является способом входа. Только временные покупки подтверждённой почты могут быть присоединены к её аккаунту.

## Что нужно от владельца и когда

| К вехе | Что |
|---|---|
| M1 | Ничего: спецификация и все решения утверждены |
| M2 | Публичный HTTPS-хост (staging-VPS или туннель) и iPhone для проверки подключения профилем |
| M3 | Аккаунт Apple Developer с ключом App Store Connect API (роль Admin) |
| M4 | При необходимости — маленький неподписанный тестовый IPA из Xcode (если zsign не примет синтетический бинарник) |
| M5 | Документация Platega из кабинета мерчанта, тестовые и боевые ключи. Сайт `docs.platega.io` из сессии планирования недоступен, поэтому в плане значения из стороннего SDK, их нужно сверить |
| M7 | VPS, DNS `xstorex.ru` и `dl.xstorex.ru`, SMTP, место для бэкапов, тексты условий, конфиденциальности и поддержки |

- Спецификация утверждена 2026-11-05 вместе с правками модели данных и вех.
- В `apps/web/app/layout.tsx` сознательно нет `viewport-fit=cover` (это зафиксировано тестом), хотя план M0 его требовал. Код считается правильным, планы M1–M7 на него не опираются.
