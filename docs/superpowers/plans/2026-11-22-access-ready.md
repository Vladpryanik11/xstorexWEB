# План: «Доступ готов» для гостя (2026-11-22)

Спецификация: `2026-11-18-xstore-v2-design.md`, §5 «Доступ готов» для гостя, §9 письмо «Доступ открыт».

Цель: гость (временный покупатель) после ручной выдачи доступа или оплаты на ту же почту входит по коду из письма и попадает на `/get/iphone`.

## Задачи

1. **Письмо `access_ready`** (`packages/mail/src/templates.ts`). Поле `email` в `MailData`. Тема «Доступ открыт» без кода; в тексте код (действует 10 минут), дата окончания и ссылка `<сайт>/signin/link#e=<почта>&c=<код>`. Тест — `templates.test.ts`.
2. **Код для выдачи** (`EmailCodeService.issueForGrant`). Без ожидания и лимитов, гасит старые коды, создаёт новый, возвращает код. Экспорт из `AuthModule`.
3. **Письмо при выдаче** (`AdminBillingService.grant`). После транзакции, без отказа выдачи: код + `mail.send('access_ready')`. Ошибки только в лог без кода. Интеграционный тест: письмо в Mailpit, код проходит `POST /auth/code/verify`, гость объединяется.
4. **`accessReady` и `provisional`** (`CheckoutService.access`, `orderView`; схемы `packages/shared/src/billing.ts`). Условие из спецификации: сессия гостя без своего доступа и не заблокирована; проверенный покупатель с этой почтой (не сотрудник, не заблокирован) имеет живое право, созданное не раньше гостя. Интеграционные тесты: true после выдачи, false для права старше гостя.
5. **Веб**:
   - `AccessReadyForm` — «Доступ готов! Введите код из письма», поле кода, «Войти», «Отправить код ещё раз»; после входа — `/get/iphone`.
   - `Wizard` (шаг ожидания/таймаут) и `AccessCard` показывают форму при `accessReady`, опрос останавливается; строка «Уже есть доступ на эту почту? Войти по коду».
   - `/signin`: гость не считается вошедшим; `?mode=code` открывает вход по коду.
   - Страница `/signin/link`: noindex, no-referrer, кнопка «Войти и подключить iPhone», без автосабмита; при ошибке — «Ссылка устарела. Войдите по коду из письма».
   - Модульные тесты компонентов.
6. **Проверки**: `pnpm lint && pnpm typecheck && pnpm test && pnpm test:int && pnpm test:e2e`, PR.
