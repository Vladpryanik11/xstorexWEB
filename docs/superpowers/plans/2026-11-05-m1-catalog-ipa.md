## 5. Инкремент: безопасный административный контур каталога

**Файлы:** `apps/api/src/catalog/admin/*`, `apps/api/src/catalog/*`, `apps/api/test/catalog-admin.int.test.ts`, `apps/web/app/admin/*`.

**Блокирующее решение R1:** без аутентифицированного staff-контекста и аудита **не публиковать** административные маршруты. Если владелец утверждает перенос минимального admin-auth/TOTP и AuditLog в M1, сначала написать их security-тесты; использовать единый модуль для дальнейшего M2. Иначе выполнять лишь закрытые серверные операции и не считать пункт «рабочая админка» закрытым.

- [ ] RED-тесты: без сессии 401, недостаточная роль 403, неверный Origin отклонён; успешная админская операция аудируется; невозможно выставить `published` без `rightsBasis` и с encrypted IPA.
- [ ] Реализовать завершение multipart и постановку `ipa.inspect` после подтверждения целостности, просмотр статусов задач, retry и безопасную отмену.
- [ ] CRUD версий, приложения, категории, подборки, статусы `draft/published/hidden`, ручная сортировка. Конфликт обновлений обработать явно, не затирать чужие изменения.
- [ ] GREEN API unit + integration; протестировать отсутствие утечки оригиналов, чужих uploads, внутренних ключей и диагностик в публичные DTO.
